# ADR-005: Cloud SQL connector with a locked-down public IP

## Status

Accepted for the first staging and production deploy.

## Context

Cloud Run needs a Postgres 16 database in `europe-west1`. A private IP would also require a VPC, a Serverless VPC Access connector or Direct VPC egress, and private service access. That is the stronger network boundary, and it costs more to stand up while the product is still on Sprint 1–2.5.

The instance still needs an IP configuration. Cloud SQL requires either a public IPv4 address or a private network.

## Decision

Use a public IPv4 address and do not add any authorized networks.

- `settings.edition` is `ENTERPRISE` so the shared-core tiers (`db-f1-micro`, `db-g1-small`) are valid. PostgreSQL 16 defaults to `ENTERPRISE_PLUS` when edition is omitted, and that edition rejects these tiers.
- `settings.connector_enforcement` is `REQUIRED`. Direct connections are rejected. Cloud Run attaches the instance with the Cloud SQL connector and talks to the unix socket at `/cloudsql/CONNECTION_NAME`.
- `settings.ip_configuration.ssl_mode` is `ENCRYPTED_ONLY`.
- `deletion_protection` and `settings.deletion_protection_enabled` are true in both environments.
- Automated backups are on in both environments. Point-in-time recovery is production only. The maintenance window is Sunday 02:00 UTC.

The database password is generated by Terraform. Secret `bizora-database-url` stores `postgres://bizora_app:PASS@localhost/bizora`. `bizora-api` and the migrate job also get `DATABASE_SOCKET_DIR=/cloudsql/CONNECTION_NAME`, which the app passes to postgres.js as the host. The password and URL are in Terraform state. The state buckets are sensitive. See `docs/deployment.md`.

## Consequences

- Nothing on the internet can open a Postgres session to the public address: there are no authorized networks, and connector enforcement rejects direct connections.
- Operators reach the database with the Cloud SQL Auth Proxy or a connector, using an identity that has `roles/cloudsql.client`.
- Private IP and a VPC remain the right follow-up before a compliance requirement or a higher threat model. Revisit this ADR then. Do not enable Pub/Sub, a VPC connector, or extra APIs until that work starts.
